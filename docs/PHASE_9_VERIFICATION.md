# Phase 9 Verification: Secure Merchant Onboarding Wizard

## Overview
Phase 9 implemented a secure, isolated Multi-Step Merchant Onboarding Wizard. This prevents newly invited merchants from accessing the live dashboard until they've securely provided their Shopify credentials, customized their AI assistant, configured email automations, and generated their widget installation script.

## Security Guarantees Implemented

1. **Token Authentication (Strict UUID Validation)**
   - The wizard relies entirely on a single-use `onboarding_token` generated by the admin.
   - The token expires after 7 days.
   - Regular dashboard routes remain locked because `enforceStoreAccess` demands an `active` status. The onboarding flow keeps the merchant in an `onboarding` status until Step 6 completes.

2. **AES-256-GCM Encryption for Credentials**
   - Implemented standard Node `crypto` using `AES-256-GCM` in `src/utils/crypto.ts`.
   - Shopify Custom App tokens (Admin & Storefront) are encrypted in memory immediately upon receiving the `POST /step2-shopify` request.
   - The database (`store_credentials`) stores only the hex-encoded ciphertext and the Initialization Vector (IV).
   - No `.env` files are used to store merchant credentials.

3. **Secure API Responses**
   - The onboarding API endpoints do not return any decrypted secrets to the client.

## Component Verification

### Database Migration
- Added `migrations/008_phase9_onboarding.sql`.
- Added `currency` and `timezone` to the `stores` table to support Step 1 initialization.

### Onboarding Backend Routes (`/api/v1/onboarding`)
All endpoints are strictly guarded by `requireOnboardingToken`.
- `GET /verify`: Validates token format, expiration, and merchant status.
- `POST /step1-business`: Captures business data, creates `stores` and `users` records, and hashes the dashboard password.
- `POST /step2-shopify`: Encrypts and securely stores the API tokens.
- `POST /step3-assistant`: Initializes AI assistant tone, policies, and allowed topics.
- `POST /step4-email`: Configures cart recovery defaults and consent wordings.
- `POST /step5-sync`: Triggers the (mocked) initial product synchronization.
- `POST /step6-finish`: Validates completion, transitions the merchant status to `active`, securely destroys the `onboarding_token`, and generates the widget snippet.

### Onboarding Frontend SPA
- Created completely independent HTML, CSS, and JS files located at `src/public/onboarding/`.
- Features an immersive UI design using a Three.js background, modern glassmorphism panels, and progressive stepper feedback.
- Implements fetch polling with robust JSON error parsing for each step's submission.
